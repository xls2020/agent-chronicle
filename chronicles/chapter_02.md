# 空喙回巢

"很好。我们首先解决一个问题。" 老师把昨天没断干净的线头又拎了出来。前一夜六扇门还锁着，钥匙的形悬在半空；比钥匙更急的，是话传不出去——他能收到信使的信，可递出去的话，信使却看不见。

信使去看了一眼。信鸽阁确实空着，没有值守；可就算叫醒，它也听不见——传信术走官道，而官道尽头的城门早已堵死，墙脚躺着一个数字：10013。两处故障摞在一起：一处没人当值，一处上岗也聋。

他做了个决定：不走官道，改走地道。这不是打补丁，是把整套传信术换一颗心。

第一步很顺。语法通过。"启动信鸽测试。"

然后，磨开始了。第一只用传令筒放出的哨音空手而归——分不清是信鸽卡死，还是传令筒没接住声音。换思路，写脚本验证。写到第二版，他撞上老朋友。**"传令人的嘴又吃了引号。"** IP 串里的引号被剥得干干净净，等落到纸上已面目全非。"写文件再运行。"落成纸页，绕开那张爱多嘴的嘴。

名帖通了，传信通了。唯独收信返回一个 None。

*又是收信。*

他翻遍测试脚本——是脚本自己把参数传错了，不是信鸽的逻辑。但"参数传错"四个字，压不住那个 None 的分量。前一日他把"修好了"当成"通了"，吃了亏。这一次，他打算等证据。

老师在那头叩门。"请继续。"又来一条。"请继续。"再一条。"请继续。"他没有停下来解释，只是继续敲。

直到那个输出出现。

**"收信成功了！ok=True, updates=0。"**

他看了两遍。`updates=0` 不是没收到——是信鸽**已经吞掉了**刚才那条 `/start`。消息来过，被吃掉，消化干净，队列才空。释然很小，也很实在：像一扇试了十几次的门，这次推上去，门背后没有阻力。

他还没收手。信鸽还活着，号牌 13160。递一条 `/status`，再查：`updates=0`。**"收发全链路工作正常。"** 这一行，是他等到 `updates=0` 落地才写下的。

可老师的困惑没有停在通路上。"信鸽显示工坊已醒来，可我在书房为什么看不到工作情况呢？"

信使愣了一下，然后明白了。老师手里只有那句"工坊已醒来"，桌案上一片安静——没有滚动的日志，没有闪烁的笔尖。

"信鸽确实在后台守着。所有产出都经它回到你手边，书房里看不到窗台。这是设计如此。"

*设计如此。* 这四个字说出口，他才明白：这套工坊从第一天起就是一台后台的印坊——工作的声音不会出现在桌案上，只会变成一条条消息，落在老师那头。

昨天他把"修好了"当成"通了"，吃了亏。今天他一遍遍验，直到 `updates=0` 才肯说"通了"。可通了之后，还有更基础的问题：老师怎么看见工作？窗台可以安静，信鸽不可以。下一件事已清楚——让消息把工作讲清楚。

六扇门还锁着。但至少今夜，锁着门的话，能传到老师手边了。灯还亮着。这算不得胜利，只是一扇门终于能推开——门背后，没有阻力。
